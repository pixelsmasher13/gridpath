Your agent edits the Excel file.
You review before it's saved.

GridPath's engine as an MCP server. Every change comes back with a review link: see each changed cell, reject what you don't want, save. 

claude mcp add gridpath -- npx -y gridpath mcp --review-required

Edits the real .xlsx. Shows you the diff.

Not a Python script that rewrites your workbook and hopes. The file you had, the cells you approved, nothing else touched.

Review before save

Every write returns a review_url: the sheet with changed cells highlighted and recomputed dependents visible, a card per agent action with before → after, and Accept, Reject, Save. With --review-required, only that page can write the file.

Leaves your Excel file intact

No re-export through a Python library, no conversion into another format. Saves rewrite only the package parts an edit touched; charts, pivots, macros, add-in data and custom XML come back byte-identical — by construction, not by the model's judgment on the day.

Fewer tokens as files get real

A tool call instead of a Python script. On a 1.4 MB, 55,000-formula model the same edit took 29 s and 1,000 output tokens through GridPath versus 68 s and 8,000 through the scripting path — same model, same prompt.

Real formulas, in process

A calculation engine (a fork of IronCalc, compiled to WebAssembly) runs inside the server. The agent reads evaluated values, writes formulas, and sees what they compute to before you ever open Excel.

Runs anywhere Node runs

One install line. No Python environment, no openpyxl, no LibreOffice recalc pass, no Excel install — which is what the “just script it” path quietly needs. Works on the locked-down laptop.

Sandboxed scripts

run_script runs the agent's JavaScript against the workbook in a worker with a hard timeout and lands the result as one reviewable batch — the right tool for “for every row where…”.

What the agent said

Claude, after editing a 1,400-row Canalyst model (2,500+ named ranges, hidden sheets) through GridPath in Cursor, asked to compare with its built-in approach.

“It recalculates live. After I changed row 58, I could read back the new growth rates right away (28.0%, 28.0%, 27.9%) and confirm the change worked. My usual approach, a Python library called openpyxl, doesn't calculate formulas. I'd have to run the file through LibreOffice to get values, and that can differ from Excel on some functions.”

“It finds things fast. Its row search and workbook map located ‘Product revenue’ and the Assumptions structure in a few calls. Otherwise I'd be scanning a 1,400-row sheet cell by cell.”

“It leaves the rest of the file alone. It rewrites only the cells that changed. When openpyxl opens and re-saves a heavy model like this one, it can quietly drop or damage charts, data validation, pivot caches or some formatting. That's the biggest risk with my built-in approach.”

      "command": "npx",
      "args": ["-y", "gridpath", "mcp", "--review-required"]

  }
}

Codex (config.toml)

[mcp_servers.gridpath]
command = "npx"
args = ["-y", "gridpath", "mcp", "--review-required"]

What a session looks like

  1. "In model.xlsx, add an FY2029E column with the same formula pattern."
  2. The agent calls describe_workbook, then run_script; the result comes back with a readback of every cell it wrote and a review link.
  3. You open the link: the new column is highlighted, the values are already computed, the card shows each formula.
  4. Accept, Save. The file on disk changes in exactly one part: that sheet.

Honest note: the newest coding agents, given a careful prompt, often preserve workbook parts on their own by editing the XML directly. GridPath's difference is that it always does, it shows you the diff first, and it needs nothing installed but Node. Numbers and methodology in the evals repo.
