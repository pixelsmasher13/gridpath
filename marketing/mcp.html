For Claude Code, Cursor and Codex

Let your agent edit Excel files. Review before anything is saved.

GridPath's engine as an MCP server. Your agent edits the real .xlsx through GridPath's tools; every change comes back with a local review link where you see each changed cell before and after, reject what you don't want, and save. Nothing touches the file until you do. 

claude mcp add gridpath -- npx -y gridpath mcp --allow ~/models --review-required

Node 20+. No Python, no LibreOffice, no Excel. Files outside --allow are refused.

Review before save

Every write returns a review_url. The page shows the sheet with changed cells highlighted and recomputed dependents visible, a card per agent action with before → after, and Accept, Reject, Save. With --review-required, only that page can write the file — the agent just hands you the link.

The real file, patched

No conversion into another format. Saves rewrite only the package parts an edit touched; charts, pivots, macros, add-in data and custom XML come back byte-identical — by construction, not by the model's judgment on the day.

Real formulas, in process

A calculation engine (a fork of IronCalc, compiled to WebAssembly) runs inside the server. The agent reads evaluated values, writes formulas, and sees what they compute to before you ever open Excel.

Runs anywhere Node runs

One install line. No Python environment, no openpyxl, no LibreOffice recalc pass, no Excel install — which is what the "just script it" path quietly needs. Works on the locked-down laptop.

Fewer tokens as files get real

A tool call instead of a Python script. On a 1.4 MB, 55,000-formula model the same edit took 29 s and 1,000 output tokens through GridPath versus 68 s and 8,000 through the scripting path — same model, same prompt.

Sandboxed scripts

run_script runs the agent's JavaScript against the workbook in a worker with a hard timeout and lands the result as one reviewable batch — the right tool for "for every row where…".

What a session looks like

  1. "In model.xlsx, add an FY2029E column with the same formula pattern."
  2. The agent calls describe_workbook, then run_script; the result comes back with a readback of every cell it wrote and a review link.
  3. You open the link: the new column is highlighted, the values are already computed, the card shows each formula.
  4. Accept, Save. The file on disk changes in exactly one part: that sheet.

Honest note: the newest coding agents, given a careful prompt, often preserve workbook parts on their own by editing the XML directly. GridPath's difference is that it always does, it shows you the diff first, and it needs nothing installed but Node. Numbers and methodology in the evals repo.
